# 隐私与安全设计

## 1. 匿名是什么，不是什么

匿名在这里只是一个展示规则，不是独立的用户身份。

- 对普通用户：匿名帖子和匿名评论只显示匿名用户，不显示昵称、公开 ID、头像和个人主页入口。前端没有匿名用户的个人主页链接，匿名帖子之间也没有共用的匿名代号，所以不能通过连续帖子或评论记录把不同匿名内容关联到同一个人。
- 对数据库内部：匿名帖子的作者字段仍然保留，方便处理恶意内容。没有这个保留，恶意辱骂和针对个人的匿名帖子就无法追责。
- 对管理员：只有管理员角色能通过管理端看到匿名帖子的作者公开 ID，而且管理端列表本身也受到角色控制。管理员查看学号还要走单独的接口，见第 2 节。
- 对作者本人：匿名不会让你失去管理权。登录后在我的帖子列表和帖子详情里，本人能看到这是自己的帖子，也能编辑和删除。判断是不是本人靠登录身份，不靠展示出来的名字。

## 2. 学号隐私，直接回答这几个问题

- 学号是否必须真实？第一版不做学校系统核验。学号在这里只是登录账号，不是已认证的身份证明。如果你以后想做学生身份认证，要把身份认证和公开展示身份分开做，不能因为核验过就把学号公开。
- 学号是否会被其他用户看到？不会。公开接口只返回公开 ID 和昵称，匿名时连公开 ID 都不返回。
- 学号是否会出现在接口响应中？公开接口不会。登录和注册返回的也是公开 ID，令牌里放的也是公开 ID，因为令牌内容只是编码不是加密，任何人拿到令牌都能解码。
- 管理员是否能直接查看所有用户的学号？不能。管理端用户列表里没有学号，只有公开 ID、昵称、角色和封禁状态。管理员要看单个学号，必须调用单独的身份查看接口并填写理由，那次查看会被记进审计日志。
- 学号是否会被用于生成公开用户 ID？不会。公开 ID 是随机生成的，与学号没有任何推导关系，拿到公开 ID 也推不出学号。
- 用户注销后，学号是否还会保留？不会。注销时账号状态改为已注销，学号会被替换成不可恢复的占位值，密码会被清空，自己的帖子和评论会改为匿名展示。审计日志里只保留公开 ID，不保留学号。

数据库内部仍然用数据库主键做关联，但这个主键也不出现在公开接口里。

## 3. 直接发布配套的风控机制

帖子直接发布，不经过前置审核，换来的是即时性，代价是必须有事后风控。

- 发帖频率限制：每人每小时最多发 10 条帖子，同一网络地址哈希每小时最多发 50 条帖子。
- 评论频率限制：每人每小时最多发 30 条评论。
- 举报系统：可以举报帖子，也可以举报评论，举报时要写原因，举报人信息不公开。
- 内容删除：管理员可以删除帖子，也可以删除评论，删除只改状态，不真正删除数据，方便审计和申诉。
- 账号封禁：支持临时封禁和永久封禁。临时封禁要填天数，到期后自动恢复；永久封禁的截止时间为空。封禁理由会记进审计日志。
- IP 限制：只作为辅助风控，不作为唯一封禁依据。发帖时网络地址只存哈希，不存原始地址，而且宿舍和教学楼经常共用出口，直接封 IP 很容易误伤。
- 手机号和身份证号不再由系统直接拦截：正文和评论里写什么，由举报和管理来处理；发帖前要先勾“我确认无违规内容”。联系方式也不再跟帖子走，存在用户资料里，发帖时用户自己选要不要公开。
- 审核记录：删帖、删评论、封禁、解封、查看学号、处理举报都会写审计日志，日志里保存管理员公开 ID、操作类型、目标和理由，不保存学号。审计日志可以在管理后台查看。

## 4. 仍然没有解决的问题，要如实说明

- 第一版没有学校系统核验，所以不能对外宣称所有账号都是真实在校学生。
- 系统不再拦截手机号和身份证号，图片里的文字、谐音和变体本来也拦不住，需要人工举报配合。
- 临时封禁到期自动恢复后，反复注册新账号规避封禁的问题只能靠频率限制、网络地址哈希辅助和人工审核缓解，不能完全杜绝。
- 注销后已经公开过的帖子内容如果被其他人截图或转发，平台无法收回，这是所有公开社区都存在的问题。
